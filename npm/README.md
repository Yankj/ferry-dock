# Ferry Dock npm entry — local, unpublished preview

This thin entry runs the same Go CLI as the native downloads. It does not
implement another server. `ferry-dock` with no arguments runs `desktop`;
explicit arguments pass to the Go executable without a shell.

The candidate version is **0.1.0-alpha.4**, with Node.js **22 or newer**.
The entry selects one exact-version optional package for the Node process's
OS/CPU: `ferry-dock-{darwin,linux,win32}-{arm64,x64}`. All seven package names
are candidates; none is reserved or published by this build. Cross-compiling a
package is not native runtime acceptance. Consult the repository platform
matrix for actual tested platforms.

There are no lifecycle scripts, runtime downloads or dependencies beyond the
matching native optional package. `--ignore-scripts` is supported. Omitting
optional dependencies prevents startup and produces an actionable error;
there is no network fallback. The entry checks the platform package version,
source identity, executable size and SHA-256 before starting it. These checks
identify packaged bytes, not a publisher signature or hostile package registry.

## Local installation

Use the current OS/CPU platform tarball **and** entry tarball generated by
`scripts/package-npm.py`. For example, on macOS Apple Silicon:

```sh
npm install --offline --ignore-scripts --no-audit --no-fund --package-lock=false --prefix ./ferry-dock-node /absolute/path/ferry-dock-darwin-arm64-0.1.0-alpha.4.tgz /absolute/path/ferry-dock-0.1.0-alpha.4.tgz
cd ferry-dock-node
npm exec --offline --yes=false -- ferry-dock version
npm exec --offline --yes=false -- ferry-dock
```

On Windows use the `win32-x64` or `win32-arm64` tarball and quote paths containing
spaces. On Linux use `linux-x64` or `linux-arm64`; the core is built with CGO
 disabled and does not require a glibc/musl shared library. This does not promise
every distribution, kernel or CPU has been tested.

No registry `npx ferry-dock` command is available from this local build. A future
registry release must publish all platform packages at the same version before
the thin entry, after the account/namespace and native acceptance are confirmed.

## Stop, cancel and update

The desktop process continues after the npm entry returns or the browser closes.
Use **Quit Ferry Dock** in its computer page to stop that owned service. Do not
kill another task's shared instance. A different-version service is rejected
rather than silently reused; finish its tasks and quit it before upgrading.

A bounded `request wait --timeout 10s` timing out does not cancel the request.
On POSIX, terminal Ctrl+C and SIGINT/SIGTERM are forwarded to the known Go child;
wait cancellation returns the Go result and leaves the request pending. On
Windows, the child shares the console, so terminal Ctrl+C reaches Go directly;
Node's programmatic `kill(SIGINT)`/`kill(SIGTERM)` is **not** a graceful Windows
cancellation mechanism. The Windows terminal event path requires a real Windows
console acceptance run. For portable automation, use bounded waits and explicit
`request cancel` only when intending to cancel the business request.

Native macOS archives/App signing and notarization constraints still apply.
Installing via npm does not establish Apple or Windows publisher trust.
